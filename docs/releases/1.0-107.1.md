# Ciclo intermediário `elite-system 1.0-107.1` — Auditoria, Build & Organização

O ciclo que **não avança para 1.0-108** (a 1.0-108 fica reservada ao
próximo ciclo funcional, depois dos testes da 1.0-107 no hardware
real): a forense byte a byte da base, o saneamento dos contratos de
teste, a otimização da esteira de build/empacotamento e a separação
explícita dos canais **testing × stable**.

## 3 · A otimização da esteira

- **compressão da ISO calibrada**: `zstd -15 -T0 -b 512K` (a era `-19`
  pagava CPU máxima pelos últimos ~2% em cima de dados já comprimidos
  — os `.pkg.tar.zst` do cache e os binários LTO+strip do Rust são
  quase incompressíveis; bloco 512K melhora throughput e razão);
- **cache Cargo unificado**: a manutenção mensal compartilha a chave do
  canal (`cargo-target-<Cargo.lock>` — o compile frio mensal morre);
- **cache do juiz**: `verify-install.yml` persiste o target do
  `craft-audit` (a compilação fria por run morre);
- **fail-fast real**: o job `build` da ISO agora precisa de
  `lint + suite` — a era pagava o build pesado em paralelo para morrer
  na porta do release com contrato vermelho;
- perfil Rust já ótimo (LTO fat + codegen-units=1 + strip + opt-level
  3 + panic abort — auditado, sem mudança).

## 4 · Testing × stable (a organização dos canais)

- **testing**: `publish-packages.yml` publica a build de validação na
  prerelease `testing` (criação idempotente, `make_latest: false`,
  dieta automática — só a build mais recente de cada pacote no ar);
  **a release estável nunca é tocada pelo canal**;
- **stable**: `releases/latest` (o endereço do `pacman.conf` de todo
  rig) recebe a build SÓ pelo fluxo explícito de promoção —
  `promover-testing.yml` (gatilho humano, depois da validação no
  hardware real): coleta a build validada, confere o selo SHA256,
  repo-add contra o db estável, upload + dieta + verificação
  db↔assets;
- a **Lei da Release Única Viva** ganha a exempção da `testing` (a
  prerelease é o canal de validação, não uma release de tag);
- **observabilidade**: resumo técnico no `$GITHUB_STEP_SUMMARY` da
  suíte, do canal testing, da promoção e do release estável (canal,
  versão, duração por etapa, tamanhos, SHA256).
