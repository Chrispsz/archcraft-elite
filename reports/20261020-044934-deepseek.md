## 4. Correção proposta

**(1) Decidir a tese em 10 s — teste falsificável, no container de build, com XferCommand ativo.** Não dá para "auditar" (a) por inspeção de log; dá para provar por experimento:

```bash
# XferCommand igual ao do preflight, 1º Server num buraco negro, 2º válido
cat >/tmp/failover.conf <<'EOF'
[options]
XferCommand = /usr/bin/curl -L -C - -f -o %o %u --retry 3 --retry-delay 3 --retry-all-errors
[probe]
SigLevel = Never
Server = http://127.0.0.1:9/repo
Server = https://geo.mirror.pkgbuild.com/$repo/os/$arch

[core]
Include = /etc/pacman.d/mirrorlist
EOF
rm -rf /tmp/fb-db /tmp/fb-cache && mkdir -p /tmp/fb-db /tmp/fb-cache
pacman -Sy --dbpath /tmp/fb-db --config /tmp/failover.conf --noconfirm core >/dev/null 2>&1
pacman -Syw --dbpath /tmp/fb-db --cachedir /tmp/fb-cache --config /tmp/failover.conf --noconfirm \
  --assume-installed core/filesystem bash bash-completion 2>&1 | tee /tmp/failover.log
grep -Ei "failed retrieving|error" /tmp/failover.log     # ← se NÃO houver 2ª tentativa, a tese (a) confirma
```
Interpretação: se aparecer download bem-sucedido do 2º Server (ou `warning: failed retrieving file ... from 127.0.0.1` seguido de sucesso silencioso), **(a) é falsa** e o problema é de janela/skew, não de failover. Rodar **também** sem `XferCommand` para isolar a variável — é o par que a tese precisa.

**(2) Fechar a evidência que falta no CI** (necessária independentemente do veredito):

```diff
-  pc=/tmp/elite-pf.conf            # conf sem stderr redirecionado
+  pc=/tmp/elite-pf.conf
+  # stderr do -Syw NUNCA suprimido: é a única prova de qual host falhou e se houve 2ª tentativa

+      grep -E "failed retrieving|invalid|signature" /tmp/elite-syw.err | sort -u | head -40
```

**(3) O fix determinístico** (alinhado à doutrina do projeto — "ZERO curl, determinístico"): não delegar o fallback ao pacman nem confiar em `--retry` (que re-tenta **o mesmo host**). O fetcher do CI já tem a lista de hosts; ele deve fazer o loop de hosts **e** gravar no `CacheDir` **real** do pacman (ou `repo-add` o gêmeo em `[elite-local]`, hoje ausente — F4):

```bash
ELITE_HOSTS=(https://cdn77.cachyos.org https://us.cachyos.org https://mirror.cachyos.org)
CACHE=$(pacman-conf --config "$pc" CacheDir | awk '{print $1}')   # NÃO hardcode /var/cache/elite-local
fetch_with_failover() {   # $1 = path relativo do repo (ex: repo/x86_64_v3/cachyos-v3/foo.pkg.tar.zst)
	local rel=$1 host rc=0
	for host in "${ELITE_HOSTS[@]}"; do
		curl -fsSL --retry 2 --retry-delay 2 -o "$CACHE/${rel##*/}.part" "$host/$rel" &&
			{ mv "$CACHE/${rel##*/}.part" "$CACHE/${rel##*/}"; return 0; }
		say "  host $host 404/falhou — tentando o próximo"
	done
	return 1
}
```
Com isso o `-Syw` seguinte é **cache hit puro** (pela LEI do projeto: sem fetch de `.sig`, sem ladder, sem skew) — e o "us primeiro" passa a ser irrelevante, o que é o ponto: a ordem resolve hoje; o fallback no fetcher resolve sempre.

## 5. Riscos

- **04d8885 (us primeiro)**: move a dependência de uma borda para outra — se o `us` atrasar num próximo push, o sintoma volta **idêntico**, agora sem o cdn77 como plano B. Além disso, a evidência (F4) mostra que "usar o gêmeo" já foi insuficiente para 5 pacotes no mesmo run; a mudança de ordem pode não fechar o resíduo.
- **Injetar pacotes CachyOS em `[elite-local]`** (recomendado em (3) como alternativa ao `CacheDir`) tem custo: `[elite-local]` é `SigLevel = Never` → você **perde a verificação de assinatura CachyOS** para esses pacotes. Preferir o `CacheDir` (pacman valida pelo sha256 do db) e usar `repo-add` só como último recurso.
- **Habilitar o stderr do `-Syw`**: volume alto (um `failed retrieving` por pacote × servidor × retry). Filtrar/`sort -u` antes de emitir, ou o log do CI fica ilegível e mascara a causa-raiz.
- **Reclassificar a mensagem "falha determinística"** do log: enquanto o CI afirmar determinismo onde há janela de skew, o próximo diagnóstico vai repetir a mesma over-claim (foi o que aconteceu entre #17, #18 e #19).
- **Escopo da auditoria**: como o log anexado é destilado, qualquer conclusão minha baseada em "ausência" (ex.: ausência de `.sig`, ausência de `Server=` da CachyOS) deve ser reconfirmada no log bruto antes de virar patch. As conclusões baseadas em **contradição** (F1, F2, F6) valem já.
