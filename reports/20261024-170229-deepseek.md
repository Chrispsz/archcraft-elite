## 4. Correção proposta

**A) nm-applet duplicado — primeiro DIAGNOSTICAR (não sei ainda qual dos dois autostarts é o seu):**
```bash
grep -rn 'nm-applet' \
  /etc/xdg/autostart/nm-applet.desktop \
  /etc/skel/.config/labwc/autostart \
  /etc/skel/.config/autostart \
  /home/liveuser/.config/labwc/autostart 2>/dev/null
```
- Se aparecer **nos dois**, mantenha UM. Preferido — deixar o XDG autostart do pacote vencer e tirar a linha manual (o motivo de instalar `network-manager-applet` era ter o binário XDG no lugar):
```bash
# [E17.x] v1.8.3 — nm-applet: um único autostart (XDG do pacote).
# O pacote network-manager-applet fornece /etc/xdg/autostart/nm-applet.desktop
# e o labwc honra XDG autostart; a linha manual no autostart do skel criava
# DOIS nm-applet (SNI 'already registered' no serial da #86).
sed -i -E '/^[[:space:]]*[^#].*nm-applet/d' /etc/skel/.config/labwc/autostart
```
- Se você **quiser** manter a linha manual, mascare o do pacote:
```bash
install -d /etc/skel/.config/autostart
printf 'Hidden=true\n' > /etc/skel/.config/autostart/nm-applet.desktop
```

## 5. Riscos

- **A (sed no autostart):** se o archcraft **nunca** teve `nm-applet` no autostart do skel, o `sed` é no-op e o duplo persiste → por isso o `grep` vem antes. Se o pacote mudar o `.desktop` para outro nome, o `Hidden=true` some e o duplo volta (por isso prefira eliminar a linha manual, não mascarar).
- **B (`wlr/window`):** remover a referência pode apagar uma funcionalidade que o dono usa (título de janela/taskbar). Confirmar visualmente no QEMU antes de remover; a troca por `wlr/taskbar` muda o layout.
- **C (`linux` ausente):** se o Rig A realmente depende de kernel stock, `nvidia-open-dkms` buildando contra headers BORE pode gerar módulo incompatível no live. **Não mexo sem a `pacman -Qq` completa** — pode ser que o perfil archiso instale `linux` por fora desse pacstrap (não visível no trecho).
- **Novo gate `pgrep -x nm-applet`:** se o binário real tiver outro `comm` (ex.: `nm-applet` truncado ou wrapper), o gate passa falso; validar com `pgrep -a` no serial antes de torná-lo bloqueante.
- **Gate `! grep -q 'Unknown module'`:** o serial do QEMU pode não capturar a linha em headless → risco de falso-negativo, não de falso-positivo (aceitável).
- **`.pacnew` delete:** varre `/etc` inteiro — um `.pacnew` legítimo de outro pacote seria apagado; é live-only, então ok, mas é broad.
