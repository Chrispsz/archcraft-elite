## 4. Correção proposta

### Patch A — `verify`: extrator robusto + integridade obrigatória + diagnóstico em falha

No step `Instalar QEMU + 7zip` (acrescentar ferramentas):

```yaml
      - name: Instalar QEMU + 7zip
        run: |
          sudo apt-get update -qq
          sudo apt-get install -y -qq qemu-system-x86 p7zip-full libarchive-tools xorriso >/dev/null
```

Substituir o step de extração por:

```yaml
      - name: Extrair kernel/initrd + UUID do marcador
        shell: bash
        run: |
          set -euo pipefail
          cd iso-out
          ISO=$(ls *.iso)
          echo "ISO=$ISO" >> "$GITHUB_ENV"
          stat -c 'ISO=%n bytes=%s' "$ISO"

          # Integridade DEIXA de ser opcional: o manifesto vem no artefato (Patch B).
          test -s sha256sums.txt || { echo "✖ sha256sums.txt AUSENTE no artefato — ISO não atestável"; exit 1; }
          sha256sum -c sha256sums.txt

          cd ..
          mkdir -p extracted

          # bsdtar/libarchive: lê ISO9660 sem os bugs de EOF do p7zip 16.02.
          if ! bsdtar -C extracted -xf "iso-out/$ISO" \
                 arch/boot/x86_64/vmlinuz-linux-cachyos-bore \
                 arch/boot/x86_64/initramfs-linux-cachyos-bore.img \
                 boot/syslinux/archiso_sys-linux.cfg; then
            echo "✖ bsdtar falhou — prova do que o ISO realmente contém:"
            xorriso -indev "iso-out/$ISO" -find /boot -type f 2>/dev/null | head -40 || true
            bsdtar -tf "iso-out/$ISO" | grep -E '(^|/)boot/(syslinux|grub)/' || true
            exit 1
          fi

          cd extracted
          ls -la arch/boot/x86_64/
          echo "── entrada default do syslinux (cmdline que o usuário boota):"
          grep -m1 '^APPEND ' boot/syslinux/archiso_sys-linux.cfg || { echo '✖ APPEND ausente'; exit 1; }
```

### Patch B — `build`: emitir e subir `sha256sums.txt`, e sanidade da ISO antes do upload

```bash
ISO=$(ls -1 out/*.iso | head -1)
( cd out && sha256sum "$(basename "$ISO")" > sha256sums.txt )
isoinfo -d -i "$ISO" >/dev/null || xorriso -indev "$ISO" -toc >/dev/null   # ISO estruturalmente fechada
stat -c 'ISO=%n bytes=%s' "$ISO"
```
E garantir que o upload do artefato inclua `out/*.iso` **e** `out/sha256sums.txt` no mesmo nível (é exatamente onde os dois jobs procuram e não acham).

## 5. Riscos

- **Patch A (trocar `7z` por `bsdtar`)**: se o caminho `boot/syslinux/archiso_sys-linux.cfg` **não existir** no ISO do Archcraft (por exemplo, perfil com GRUB-only no live), o `bsdtar` retorna erro diferente do `7z` e o step continua vermelho — mas agora com o dump (`xorriso -find`) provando o fato, em vez de um "Data Error" opaco. Degradação aceitável: o step passa de "misterioso" para "diagnosticável".
- **Patch A (sha256 obrigatório)**: sem o Patch B no mesmo PR, **toda** run fica vermelha em `test -s sha256sums.txt`. Os dois têm de ir juntos.
- **Patch A (`libarchive-tools` + `xorriso`)**: +~2 MB no `apt-get`, e `bsdtar` preserva paths idênticos ao `7z` (sem mudança no resto do step).
- **Patch B (`isoinfo`/`xorriso -indev`)**: consumiria ~2,9 GB de leitura adicional no disco do runner — se o runner já estiver apertado com o `airootfs` + ISO, prefira apenas `stat -c%s` + o `xorriso -indev -toc` (lê só os descriptors, é barato).
- **Patch C**: `Scheduled restart job` é legítimo em serviços com `Restart=always` saudáveis; por isso ele **avisa** e não falha — se virar gate duro, gera falso vermelho em `systemd-resolved`/`NetworkManager`.
- **Risco de cobertura não coberto por nenhum patch**: enquanto o boot serial do live não rodar (`serial-verify.log` inexistente), **toda** validação de dock/waybar/CSS do v1.8 é não-testada. Vale considerar um gate explícito que falhe se `serial-verify.log` não existir depois do boot — hoje o `upload-artifact` só emite `##[warning]`.
- **Incerteza residual**: se o `verify-install` tiver caído no fallback `última bem-sucedida`, a conclusão "ISO sã" precisa ser refeita — e aí o suspeito número 1 passa a ser o `mkarchcraftiso`/espaço em disco do runner no fechamento da ISO. **A linha que falta é a URL baixada no step `Baixar ISO (tag > run_id > última bem-sucedida)`** (janela 00:37:44–00:41:44 do job `verify-install`, omitida no recorte). Sem ela, não afirmo qual das duas causas é a real.
