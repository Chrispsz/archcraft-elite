## 3. Resposta direta às duas questões

### (1) Selo `file:///var/lib/pacman/sync` → pacstrap offline

**Confirmado na lógica, não re-provado nesta evidência.** A cadeia é correta: com `Server = file:///var/lib/pacman/sync`, o `pacstrap -Sy` busca `{server}/{repo}.db` = cópia local sobre si mesmo → zero rede; pela lei validada no #17, cache hit **não** gera fetch de `.sig` (só download ao vivo). Logo todo o tráfego de rede migra para o preflight (`-Syw` + escada), e o pacstrap vira determinístico. A evidência anexada é um audit de URLs — **não contém o conf selado nem log de pacstrap**, então a prova do selo é a memória de campo (#17), não este relatório.

**Precondição de superfície única**: *toda* seção do conf selado precisa de `.db` presente em `/var/lib/pacman/sync` no momento do pacstrap. Se faltar um (falha de ordem: geração do `[elite-local]` vs preflight), o fetch `file://` falha **localmente** — não é curl, mas derruba o build. O §1 admite a lacuna:

```
Servers `file://` ([elite-local]) não aparecem aqui — repo gerado no próprio CI, não probeável.
```

E o §1 **não inclui `core.db` / `extra.db` / `multilib.db`** (seções Arch vêm de `Include=`, não seguido pelo auditor).

### (2) Riscos residuais de curl error

Pós-preflight: **zero curl por construção** (selo). Veredito: "0 falhas reais" é correto **para as URLs auditadas**; "0 risco de curl no CI" requer também (a) ser coberto.
