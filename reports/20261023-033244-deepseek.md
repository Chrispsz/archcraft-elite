## 5. Riscos

- **Risco da correção `cancel-in-progress: false`:** duas ISOs podem construir em paralelo se dois pushes vierem em sequência; consome runner e pode colidir em publicação de release. Alternativa: manter o gate no `lint` (barato) e só marcar `cancel-in-progress` na run inteira.
- **Falso verde por run cancelada vs. run verde:** `conclusion: cancelled` **não é** sucesso. Se algum downstream tratar "não-failed" como OK, um release pode sair sem ISO. Conferir os `if:` de `release`/`verify` para não engolirem `cancelled`.
- **Ruído do shfmt no log do lint:** o diff gigante polui a triagem e mascara o que importa. Manter shfmt como "informativo" está certo, mas convém **commitar um `shfmt -w`** de uma vez para o diff sumir e o log voltar a ser legível — é higiene, não bloqueio.
- **Falta de log do `build`:** se o pipeline tiver upload de log só no `always()` e o cancelamento cortar antes do upload, futuras run canceladas serão igualmente cegas. Considerar `actions/upload-artifact` com `if: always()` no início do build para preservar o parcial.
