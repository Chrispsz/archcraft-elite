## 4. Correção proposta

Corrigir na **fonte** (onde os `style.*.css` são gerados/copiados para `~/.config/waybar/`), não no runtime.

```bash
# 1) localizar os fontes dos CSS da sessão
grep -rn -E '(icon-size|max-(width|height))[[:space:]]*:' elite/ scripts/ .ci/ 2>/dev/null

# 2) patch nas CSS (ex.: os style.top.css / style.dock.css do skel/sessão)
#    icon-size  (GTK3)  →  -gtk-icon-size  (GTK4)
sed -i -E 's/(^|[[:space:]])icon-size([[:space:]]*:)/\1-gtk-icon-size\2/g' \
       style.top.css style.dock.css
#    max-width  (inexistente no GTK4)  →  remover; usar min-width só se quiser tamanho fixo
sed -i -E '/^[[:space:]]*max-width[[:space:]]*:/d' style.top.css style.dock.css

# 3) sweep preventivo: outros GTK3-ismos que também derrubam o waybar
grep -nE 'icon-size|max-(width|height)|-gtk-icon-effect|border-image|-gtk-gradient|icon-shadow|^[[:space:]]*outline' \
     style.*.css
```

Diff conceitual de cada linha:
```diff
-  icon-size: 16px;      /* GTK3-only */
+  -gtk-icon-size: 16px; /* GTK4 */
...
-  max-width: 220px;     /* inexistente no GTK4 */
```
O ponto 3 é o essencial: como o waybar **aborta na primeira** propriedade inválida, você só descobre a linha 111/117; pode haver mais abaixo. Faça o sweep e só feche quando o probe retornar `BARS_EXITS=0`.

✔ waybar sem NENHUMA morte na sessão (BARS_EXITS=0)

## 5. Riscos

- **`-gtk-icon-size` pode não reproduzir o tamanho visual pretendido** por `icon-size` (semântica GTK4 ≠ GTK3) → risco **estético**, não funcional.
- **Remover `max-width`** pode deixar um elemento do dock crescer. Se o objetivo era tamanho fixo, troque por `min-width` (ou resolva no `config.dock` do módulo) — nunca reintroduza `max-width`.
- **Whack-a-mole:** o waybar sai na 1ª propriedade inválida; há risco de sobrar outro GTK3-ismo (ex.: `outline`, `-gtk-gradient`, `border-image`). O ponto 3 mitiga.
- **Validade do `-gtk-icon-size`** depende do build GTK4 do waybar `0.15.0-3.1`; se ainda reclamar, a alternativa é dimensionar via `font-size` no módulo. Testar no gate antes de fechar (a ISO é descartável).
- **Sem risco** em pacstrap/calamares/Kernel/GRUB: nada disto foi tocado e os gates respectivos estão verdes (`verify-install` = success; forense = success).
- Fica como pendência separada (missão zero-curl): os 7× `curl: (22) 404` do preflight — self-healed, mas ainda é superfície de skew CachyOS.
