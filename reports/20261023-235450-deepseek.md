## 4. Correção proposta

### 4.1 Patch primário (CSS) — remover a classe inteira, manter só `min-width`

Localize primeiro (o caminho real do overlay pode variar):

```bash
grep -rnP '(?<!min-)width\s*:' elite/ --include='*.css'
```

O alvo é a linha 120 do `style.dock.css` do dock v3 (separador). O diff conceitual:

```diff
 #custom-separator {
     background-color: #4c566a;
     min-width: 1px;
-    width: 1px;      /* inválido em GTK CSS → waybar 0.15 aborta o parse */
+    /* min-width já pina 1px; 'width' não existe no GTK CSS */
 }
```

Varredura defensiva (apaga só linhas cujo **property name** é `width`/`max-width`; não toca em `min-width`):

```bash
# 1) backup + limpeza
for f in $(grep -rlP '(?<!min-)width\s*:' elite/ --include='*.css'); do
  cp -a "$f" "$f.bak-v1.8.1"
  perl -ni -e 'print unless /^\s*(?:max-)?width\s*:/' "$f"
done

# 2) prova de que zerou (tem que sair vazio)
grep -rnoP '(?<!min-)width\s*:' elite/ --include='*.css' || echo "OK: nenhum width/max-width em CSS de barra"
```

> Se algum seletor **precisava** de largura fixa maior que o conteúdo (ex.: `#custom-logo { width: 20px }`), não apague — **converta** para `min-width`:
> `perl -pi -e 's/^(\s*)width(\s*:)/${1}min-width${2}/' "$f"` (semântica GTK equivalente para box sem expand).

### 4.2 Patch sistêmico (fechar o buraco dos contratos)

Adicione ao conjunto de contratos o ban da **classe**, não dos dois nomes que já apareceram:

```bash
# ── [contrato] GTK CSS: width/height não existem (só min-*). waybar 0.15 = exit 1.
bad="$(grep -rnoP '(?<!min-)(?:max-)?(?:width|height)\s*:' elite/ --include='*.css' || true)"
if [[ -n "$bad" ]]; then
  report_fatal "propriedade GTK-CSS inexistente (width/max-width/height/max-height) em CSS de barra — waybar 0.15 sai exit 1" "$(wc -l <<<"$bad")"
fi
```

O lookbehind `(?<!min-)` deixa `min-width`/`min-height` passarem e pega `width`, `max-width`, `height`, `max-height` — a "classe inteira" que o commit dizia caçar.

### 4.3 Ajuste do gate (opcional, reduz falso-verde)

`WAYBAR_COUNT≥2` não prova sanidade quando o dock ressuscita em loop. Exija `BARS_EXITS==0` para emitir o ✔ de "sessão VIVA" (ou reporte `WAYBAR_COUNT` como máximo observado, não amostra instantânea). E troque a causa na mensagem:

```diff
- chk $? "waybar sem NENHUMA morte na sessão (BARS_EXITS=${BE:-?})" "waybar morreu ${BE:-?}× na sessão — crash/race/OOM (exit code no BARS| acima)"

```

### 4.4 Verificação

Não há como validar localmente sem subir a sessão — **o próprio gate é o teste**: após o patch, `BARS_EXITS` tem que ser **0**. Se voltar `exit=1`, a linha/coluna do `[error]` no `BARS|` aponta a próxima propriedade.

## 5. Riscos

1. **`perl -ni` apaga a linha inteira.** Para `min-width` não há efeito; mas se havia `width` de dimensionamento real, o elemento colapsa para o tamanho do conteúdo. Mitigação: rodar o `grep` do 4.1 passo 2 antes e inspecionar cada hit — usar a conversão `width`→`min-width` (4.1 nota) nos casos de largura fixa.
2. **Semântica `max-width` ≠ `min-width`.** Onde o intento era *teto* (cap) e não *piso*, converter muda o layout. No separador o intento é pino de 1px → `min-width` correto. Auditar os outros hits um a um.
3. **Regex de contrato com `-P`.** O CI usa `grep -P`? Se o shellcheck/lint rodar em busybox ou o grep do container não tiver PCRE, troque por `awk`/dois-passos. Confirme `grep -P` disponível no estágio do contrato.
4. **Novos falsos-positivos do contrato:** se algum CSS legítimo usa `width` dentro de comentário, o ban dispara. Estreite para linhas não-comentário (`sed 's,/\*.*\*/,,g'`) antes do grep, ou aceite o ruído (mais seguro que deixar passar).
5. **O `min-width: 1px` sozinho pode não bastar** se o waybar/GTK aplicar `padding`/`margin` residual no separador — nesse caso o pixel vira 1+padding. Se o dono exigir exatamente 1px, use um `box` sem conteúdo com `min-width: 1px; padding: 0; margin: 0`.
6. **Nada do patch toca o sistema instalado** — `verify-install` continuará verde; o risco de regressão fica contido ao live.
