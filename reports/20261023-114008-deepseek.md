## 4. Correção proposta

### 4.1 Patch mínimo (obrigatório) — silenciar SC1090 de forma localizada

```bash
# elite/airootfs/usr/local/bin/craft-idle
@@
-[ -r "$CONF" ] && . "$CONF"
+# SC1090: o caminho é configurável em runtime; o source é intencional.
+if [ -r "$CONF" ]; then
+  # shellcheck source=/dev/null
+  . "$CONF"
+fi
```

Por que não a variante "inline" (`... && . "$CONF"  # shellcheck disable=SC1090`): a forma `if` acima resolve **dois** problemas de uma vez — o SC1090 e o status de saída. Com `set -e`, `[ -r "$CONF" ] && . "$CONF"` como **última** linha do script faz o script terminar com status **1** quando `$CONF` não é legível (a falha do `[ -r ]` está isenta do errexit, mas o status final da lista não). Se `craft-idle` for acionado por unit systemd `Type=oneshot`, isso vira `failed` silencioso — **exatamente o padrão que a v1.5.2 caçou no `fg-booster`**. (Hipótese a confirmar lendo o arquivo: se a linha não for a última, o erro é apenas de lint.)

Alternativa conservadora, se preferir mudança de uma linha só:
```bash
[ -r "$CONF" ] && . "$CONF"  # shellcheck disable=SC1090
```

## 5. Riscos

1. **Falso verde por supressão ampla**: usar `# shellcheck disable=SC1090` no topo do arquivo ou `-e SC1090` no gate mataria a detecção de `source` malicioso/injeção em **todos** os scripts. Manter a diretiva colada na linha.
2. **Regressão silenciosa no status de saída**: trocar `&&` por `if` muda o exit code do script — se algum arquivo/unit depende de `craft-idle` retornar 1 quando não há CONF (improvável, mas possível), haverá mudança de comportamento. Verificar o consumidor antes de aplicar.
3. **Rodada ainda sem auditoria real**: com o lint corrigido, o próximo run finalmente chega ao pacstrap e só então os itens (1)–(6) terão log. Não presuma que a ausência de `Failed with result` nesta run significa ausência de crash-loops.
4. **`relay-agents` já queimou duas auditorias** para uma run sem artefato; se os agentes emitirem veredito, descarte — é a "tese sem evidência" do incidente #17/#6 de novo.
